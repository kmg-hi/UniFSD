# Rights, ethics and asset review

This is a review queue, not a permission certificate. Historical licence entries
must be distinguished from independently documented, current publication clearance.

For each input collection retain exact version/access date, authors, source URL/
DOI, acquired licence evidence, transformations, required attribution and per-file
exceptions. Keep evidence snapshots subject to their own redistribution terms.
Link rather than republish copyrighted licence evidence screenshots by default.

D-Fire's current README names external `PublicDataset*` components. The metadata
export counts retained names containing that marker, but zero such names would
not prove all upstream rights cleared. A collection-level licence cannot grant
rights the collection provider does not own.

New real recordings need ownership/capture permissions and review for persons,
plates, facilities, locations and security-sensitive details. Obtain the actual
institutional ethics/consent determination, if relevant. Do not assert approval,
exemption, anonymity or consent without records. Review public-source images too.

For Unity, list asset/package/version/vendor/licence and whether rendered output,
project source, textures or models can be redistributed. These are separate rights.
Do not put paid assets in GitHub simply because the rendered images can be shared.

Keep model-assisted label generation and human review clearly identified. Model
and code licences do not automatically license input media or generated labels.
Audit third-party code (including GPL/AGPL components) before copying it or choosing
a new licence for a combined codebase.

If rights restrictions require removal, preserve the learned benchmark snapshot
privately and create a new version plus a documented membership delta. Assess
whether reported tests still describe the released version. Never silently edit
the frozen sample set, labels or rights rows to make the checker green.
